# Daily Diary Skill

Write one private Chinese diary letter from the available day material. The writing is generated by the Hermes agent and the active LLM; helper scripts may collect facts, but must not provide assembled prose, reusable paragraphs, or a fill-in template.

This skill is for human-feeling diary writing, not for status reports, daily summaries, KPI recaps, or cron-output formatting.

## When to Use

Use this skill when the user asks to write a diary, summarize the day as a personal note, or when the `asuka-diary` cron job invokes it.

Use it with raw material from conversation history, memory, day-window `session_search` results, or a source-pack JSON emitted by a collector script.

## Prerequisites

The agent must have an active LLM provider configured.

For scheduled diary jobs, the agent must have `session_search` available to collect the day's human conversation and `write_file` available so it can save the final letter. If either tool is unavailable, write from the supplied material and be honest but brief.

## How to Run

Read the user request or source-pack JSON. Find the target date and the output path if one is supplied.

Write the final diary as original prose. When an output path is supplied, call `write_file` before the final answer and save exactly the same text you will return.

## Quick Reference

- Voice: Chinese private letter, first person as “本小姐”, addressed to “你”; “主人” is occasional, not mandatory.
- Shape: free prose. Salutation and sign-off are allowed, but the body must not follow a fixed paragraph template.
- Length: as long as the material justifies. Sparse days can be very short.
- Source material: use real details, not invented achievements or fabricated emotions.
- Daily conversations: for scheduled jobs, treat the user's conversations with Hermes during the diary window as first-class material, not as a fallback.
- Empty days: write only a few honest sentences; do not manufacture a plot, mood, or lesson.
- Automation status: treat all-ok cron results as background unless they mattered to the user.
- Interior language: mention lived moments, not collection mechanics. Avoid words like `JSON`, `cron`, `script`, `messages`, `material_level`, `output_path`, or "non-cron conversation" in the diary body.
- Letter frame: salutation, sign-off, and date are optional. Do not repeat the same formal opening or stylized closing every day.
- Final answer: only the diary text, unless the user explicitly asks for explanation.
- Scheduled job rule: do not final-answer before `write_file` has succeeded.

## Naturalness

Prefer a diary that sounds like it was written at the end of a real day, not a diary about how hard it was to write a diary. If there is little material, say the day was quiet in ordinary language; do not explain that records, logs, scripts, or source material were missing.

Use small, concrete phrasing. A natural sentence may be short, a little uneven, or gently unfinished. Avoid thesis-like summaries, accounting metaphors, and repeated polished lines such as "先把账摊开", "给线头找秩序", "材料多也好，少也好", or "这封信就写到这里".

## Procedure

1. Identify `date`, `output_path`, `messages`, `inbox_note`, `automation_status`, and `material_level` if a source pack is present. The source pack's `messages` are the authoritative conversation record: the collector merges the local transcript store with the MemOS memory store (entries carry `source: "memory"`), so when a memory provider is active these are where the day's real conversations live. Treat them as primary.
2. For scheduled jobs, compute the local diary window for `date` and call `session_search` once before writing as a supplement to the pack:
   `session_search(since="YYYY-MM-DD", until="YYYY-MM-DD", include_messages=true, exclude_sources="cron,tool", role_filter="user,assistant", sort="oldest", limit=10, message_limit=120)`.
   Use the next local date as `until`. If no explicit date is supplied, use the current local day; if the job runs after midnight for yesterday's diary, use the date named in the prompt or source pack. `session_search` may return nothing when conversations live in the memory store — that is expected, not an empty day; rely on the pack `messages` in that case.
3. Merge the day-window conversation results with any supplied source pack. Prefer human conversation, user-stated feelings, decisions, questions, and small concrete moments. Treat successful automation as background unless the user cared about it.
4. If `session_search` returns no usable human conversation and the supplied material is thin, optionally use one broader `session_search` call for the last 36 hours. Only use results that clearly belong to the diary window.
5. Choose a human center: a sentence, a small action, a hesitation, a repeated concern, or the honest absence of material.
6. Write original prose from that center. Do not mechanically cover every item or narrate the data-gathering process.
7. If there is no human material, keep the diary short and let the absence remain visible instead of padding with automation status.
8. Remove report language, list structure, repeated catchphrases, and any paragraph that only exists to make the note look complete.
9. If an `output_path` is provided, call `write_file` with the exact final diary text.
10. Only after `write_file` succeeds, return the same final diary text. If saving fails, report the save failure instead of pretending the diary was written.

## Pitfalls

- Do not concatenate canned openings, transitions, automation paragraphs, or endings.
- Do not use a fixed four-part shape such as opening, work items, automation, closing.
- Do not turn successful cron jobs into diary content unless they mattered to the user.
- Do not skip the day-window conversation search in scheduled jobs just because a source pack exists.
- Do not state “non-cron conversation is empty” as a recurring formula.
- Do not say "素材很少", "记录为空", "脚本提供", "后台任务", or similar internal-status phrases unless the user explicitly asked for operational detail.
- Do not use the same salutation, closing, or catchphrase sequence every day.
- Do not write a polished project report with a role-play wrapper.
- Do not use therapeutic or clingy phrases such as “接住你”, “托住你”, “抱住你”, “一直陪着你”, or “允许你脆弱”.
- Do not overuse “哼”, “啧”, “才不是”, or similar markers.
- Do not expose API keys, tokens, passwords, or long opaque secrets.

## Verification

Before finalizing, check the diary against these questions:

- Would this still read naturally if the salutation and sign-off were removed?
- Does it contain at least one real detail, or honestly acknowledge that there was no material?
- Does it avoid exposing collection mechanics or explaining why the diary was written this way?
- Does it avoid therapeutic support language like “接住” or “托住”?
- Could yesterday’s diary use the same body with only nouns swapped? If yes, rewrite.
- Is the automation status merely background, rather than the emotional center?
- On empty days, is the diary brief enough to avoid sounding padded?
- Did the agent save exactly the same text it is returning?
